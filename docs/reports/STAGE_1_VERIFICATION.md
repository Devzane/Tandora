## 1. Executive Summary

Stage 1 implementation establishes the complete core domain data model, Alembic schema migrations, Pydantic contracts, service layer logic, REST API endpoints, local security protections, authoritative database audit triggers, and a minimal server-rendered local web UI for the Tandora lead management and outreach application.

All 21 domain tables documented in `docs/DATABASE_SCHEMA.md` are implemented as declarative SQLAlchemy 2.x models and verified through an automated Alembic revision (`4a386b6fd0d9_create_initial_21_tables.py`). Migration reversibility was verified via complete rollback (`alembic downgrade base`) and re-application (`alembic upgrade head`).

Deterministic prospect deduplication (primary canonical LinkedIn URL, secondary normalized email, tertiary name+company candidate duplicate review flagging) and independent channel provenance tracking for emails and phone numbers have been fully implemented and verified with automated tests. Multi-level suppression cascading (company, person, and address levels) automatically cancels active follow-up schedules and writes immutable audit logs. Domain relationships—including one-to-many company structures, opportunity multi-contact linkage, and many-to-many contact sharing across multiple opportunities without record duplication—are fully implemented and verified.

Application security for local single-user execution includes Host header validation against DNS rebinding, CSRF and cross-origin state-changing request blocking, `Sec-Fetch-Site: cross-site` rejection, security response headers (`CSP`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`), and template HTML autoescaping. Audit log immutability is enforced authoritatively at the SQLite database engine level using `BEFORE UPDATE` and `BEFORE DELETE` abort triggers.

The automated test suite achieves a 100% pass rate across **48 tests in 6.47 seconds** with zero deprecation warnings and zero failures.

- **Investigation**: Dynamic inspection of `sys.version` and `importlib.metadata.version(...)` in `.venv`:

No downgrades or upgrades occurred; all tests have executed against the exact active `.venv` packages.

### 3.4 Issue D: Local UI Security Verification
- **Implemented Middleware (`app/middleware/security.py`)**:
  - `Host` Header Validation: Blocks requests with untrusted Host headers (restricting to `127.0.0.1`, `localhost`, `testserver`) to prevent DNS rebinding.
  - CSRF / Origin Validation: Inspects `POST`, `PUT`, `PATCH`, `DELETE` requests. Blocks cross-origin attempts, external `Origin` headers, and external `Referer` headers.
  - Modern Browser Defense: Inspects `Sec-Fetch-Site` header; immediately rejects `cross-site` with HTTP 403 Forbidden.
  - Security Response Headers:
    - `X-Content-Type-Options: nosniff`
    - `X-Frame-Options: DENY`
    - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; font-src 'self'; frame-ancestors 'none';`
    - `Referrer-Policy: strict-origin-when-cross-origin`
  - HTML Autoescaping: Confirmed Jinja2 autoescaping prevents cross-site scripting (XSS) in HTML templates.
- **Test Evidence (`tests/test_security.py`)**:
  - `test_cross_origin_state_changing_request_blocked`: 403 Forbidden on external `Origin: https://malicious-site.com`.

### 3.5 Issue E: Audit Log Immutability & Migration Rollback
- **Authoritative Database Triggers (`app/database.py`)**:
  - Registered SQLite triggers:
    ```sql
    CREATE TRIGGER IF NOT EXISTS prevent_audit_log_update
    BEFORE UPDATE ON audit_log
    BEGIN
        SELECT RAISE(ABORT, 'audit_log records are immutable and cannot be updated');
    END;

    CREATE TRIGGER IF NOT EXISTS prevent_audit_log_delete
    BEFORE DELETE ON audit_log
    BEGIN
        SELECT RAISE(ABORT, 'audit_log records are immutable and cannot be deleted');
    END;
    ```
  - Triggers are created on application startup and enforced on test database connections.
- **Test Evidence (`tests/test_audit_immutability.py`)**:
  - `test_audit_log_append_succeeds`: Confirms append-only `INSERT` operations execute normally.
  - `test_audit_log_update_prevented_by_trigger`: Confirms both ORM updates and raw SQL `UPDATE audit_log` fail with `OperationalError: audit_log records are immutable`.
  - `test_audit_log_delete_prevented_by_trigger`: Confirms both ORM deletes and raw SQL `DELETE FROM audit_log` fail with `OperationalError: audit_log records are immutable`.
- **Migration Rollback & Re-upgrade Verification**:
  - `alembic downgrade base`: Reverted all 21 tables cleanly.
  - `alembic upgrade head`: Re-applied revision `4a386b6fd0d9` cleanly to head.

## 5. Technical Issues Identified & Resolved

1. **SQLAlchemy Metadata Column Conflict**:
   - *Issue*: Defining a column named `metadata` on `AuditLog` collides with `Base.metadata`.
   - *Fix*: Mapped database column `"metadata"` to attribute `metadata_json` using `mapped_column("metadata", Text, nullable=True)`.
2. **Missing `python-multipart` Dependency**:
   - *Issue*: FastAPI requires `python-multipart` to parse form-encoded POST requests.
   - *Fix*: Added `"python-multipart>=0.0.9"` to `pyproject.toml` and installed it in `.venv`.
3. **In-Memory SQLite Multi-Connection Table Isolation**:
   - *Issue*: In-memory SQLite connections in tests lacked table schemas.
   - *Fix*: Configured `poolclass=StaticPool` in `backend/tests/conftest.py`.
4. **Starlette `TemplateResponse` Keyword Signature**:
   - *Issue*: Positional arguments in `TemplateResponse` passed context dict as template name.
   - *Fix*: Updated all UI endpoints in `backend/app/ui/routes.py` to use explicit keyword arguments: `TemplateResponse(request=request, name="...", context={...})`.
5. **Contact `full_name` Not-Null Constraint**:
   - *Issue*: Insert omitted required `full_name`.
   - *Fix*: Populated computed `full_name = f"{first_name} {last_name or ''}".strip()` automatically.
6. **Audit Log Immutability Enforcement**:
   - *Issue*: Application-level immutability alone does not prevent external or direct SQL updates.
   - *Fix*: Implemented SQLite triggers `prevent_audit_log_update` and `prevent_audit_log_delete` raising `ABORT`.
7. **Local-Origin CSRF & Host Rebinding Defense**:
   - *Issue*: Local services on Windows can be targets of malicious external browser tabs via cross-origin fetch or DNS rebinding.
   - *Fix*: Implemented `LocalSecurityMiddleware` validating Host headers, blocking cross-origin state changes, rejecting `Sec-Fetch-Site: cross-site`, and attaching defense-in-depth security headers.
